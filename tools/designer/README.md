# Facet Design

Facet Design is a visual UI builder made with Facet controls. The Studio plugin
and the companion experience use the same editor, document format, control
adapters, and code exporter.

## Who it serves

Designers can build game interfaces with the same controls that the game uses.
Developers can export a Facet component and connect it to game state. Humans and
agents can edit the same supported component through visual tools and source.
The editor adds adapters around existing controls; it does not change their APIs.

## Work together

A human can select a layer, change its spacing or text, and export a linked
component. An agent can inspect that component and apply a validated batch of
property or layer edits. When the updated source reaches the linked Studio
ModuleScript, the canvas updates and the edit enters Undo history. The human can
review the result visually and continue editing the same source.

This workflow shares a supported source format. It does not provide simultaneous
multi-user editing or merge concurrent code changes. File edits need a Studio
file-sync connection or an explicit update to the linked ModuleScript. Custom
callbacks and external expressions pause visual source writes to protect the code.

## Build

Run `tools/designer/build.sh` from the repository root.

- `build/Facet-Design.rbxm` is the Studio plugin.
- `build/Facet-Design-Playground.rbxl` is the companion experience.

Open the place in Studio to try the editor. For the plugin, use Studio's local
plugin installation workflow with the model. Open **Plugins → Facet Design →
Design**.

## Design

Start from one of six templates in the live visual gallery. Search the gallery to find a design. Select a layer or select a control on the canvas. Use
**Insert control** to add any of the 63 public control constructors. Edit its
properties in Inspector. Structured properties, such as table rows, menu items,
and navigation pages, have a data editor. Duplicate, delete, reorder, and move
layers between containers. Drag the whole layer row to reorder it. Drop before a
row to use that row's container. Double-click a layer name to rename it. Return commits the name; Escape cancels it. Undo and Redo restore
both the design and its selection. Undo also restores the previous design after
you load a template or a saved design. Use Reset to restore a property default.

Desktop starts in **Fit** with Layers, Canvas, and Inspector visible together.
Compact screens start in **Width**. Use **Width** zoom to keep the canvas readable. Scroll to see the rest of the
screen. Use **Fit** to see the whole screen at once.

Use **Interact** to try the controls. Use **Select** to edit them. Change the
preview device, orientation, palette, text size, and zoom. Compare devices or palettes side by side. Comparison canvases own separate local
state. On compact screens, use **Canvas**, **Layers**, and **Inspector** tabs.
The phone header keeps the design name, Undo, Redo, and Design commands visible.
Use the + button beside the pane tabs to insert a control. Preview settings scroll
horizontally. Menus filter while you type. Use Clear to restore the full list.

**Files** imports or exports a validated JSON design file. My designs has live
previews and actions to rename, duplicate, remove, and restore designs.

**Save** adds the design to **My designs**. The plugin stores designs with native
plugin settings. The companion experience stores each player's library with
server DataStores. It saves the draft after edits and sends an immediate save
when the player presses Save. Keep the session open until the cloud-save status
confirms success. Unpublished places and failed loads use local editing mode;
they cannot overwrite an existing cloud library. Concurrent sessions cannot
silently overwrite each other's library. A library supports 40 saved designs,
500 controls per design, and 900 KB of serialized data.

## Source

**Export Luau** in the plugin creates a component ModuleScript and a `.preview`
ModuleScript in `ReplicatedStorage.FacetDesigns`. The component uses the current
Facet API and does not require the editor. Export also links the component to
the editor. **Import** links a selected supported component.

Visual edits update linked source with `ScriptEditorService.UpdateSourceAsync`.
Supported source edits update the canvas, including edits to closed scripts.
Studio records source changes with ChangeHistoryService. **Code → Apply code**
lets the experience edit the supported component format too. On a phone, code
export displays selectable Luau; the Studio plugin creates ModuleScripts.

The source reader supports the portable format generated by this editor. It
rejects arbitrary execution, custom callbacks, external state expressions, and
unsupported syntax. If linked code contains those expressions, the editor
retains it and pauses visual source writes. Restore supported code or load a
new template before editing visually. General game code does not yet round trip.

Agents can inspect and edit portable components with the
[batch edit command](agent-editing.md). Supported external edits enter visual
history and can be undone.

All public control constructors have adapters. This does not mean every optional
Facet property has an inspector, or that custom game behavior and 3D scene
contents have visual editors. Stage currently exposes its size and camera field
of view. Image controls accept asset references. Stateful controls expose their
initial state; consumer game logic belongs in the exported component.

## Publish the companion

Open the built place. Use **File → Publish to Roblox** to create a new experience
named **Facet Design**. Select all device platforms offered by Studio. Keep its
audience **Private**. Do not replace an existing experience. DataStores work on
published Roblox servers; Studio API access is not required for phone use.

The project uses Sensor screen orientation and native device safe insets. Phone
and tablet layouts were checked in Studio's Device Simulator. Physical phone,
console, VR, and production DataStore checks remain separate verification.

## Implementation

The document is bounded authoring data. Rendering calls `Facet.controls(runtime)`
directly. Compose owns the native tree, cells, formulas, branches, and cleanup.
There is no additional application runtime. Facet's controls supply the editor's
buttons, text inputs, typography, and styles.

Roblox supplies `UIListLayout`, `UIGridLayout`, constraints, `ScrollingFrame`, `TextBox`,
`UIDragDetector`, input contexts, StyleSheets, and native selection. The plugin
uses `CreateDockWidgetPluginGuiAsync`, `GetSetting`, `SetSetting`,
`ScriptEditorService`, and `ChangeHistoryService`. The experience uses server
`DataStoreService.GetDataStore`, `GetAsync`, `UpdateAsync`, and a validated
`RemoteFunction`. The custom policy is the authoring document, adapter recipes,
source reader, history, and storage revision checks.
