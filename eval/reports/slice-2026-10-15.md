# FacetBench slice: 2026-10-15

This measurement has one run per arm on one slice, with seed 1 and
`gpt-6.1-sol` at medium effort. It does not establish a general Facet quality,
cost or performance claim. The judge was not run. External transfer requires
the owner's approval. No data was sent to an external service in this work.

The saved runs are in
`artifacts/facetbench/slice/runs/racing-hub-slice/{plain,facet}/codex-sol/seed-1`.
The agents were not run again. Verify repeats only the hidden checks and
audits against each saved workspace. It archives the previous result, checks
and captures in that run's `rechecks` directory. Agent metrics, transcript,
timestamps and `agent.rbxlx` stay as recorded.

After the correction, Plain passes no universal device case. Facet passes the
purchase-and-wallet case on each device. Both builds still fail the complete
universal gate. These are recorded UI assertion failures, with the strong
reference passing the same checks. The report remains FAIL and judge evidence
remains missing.

## Cause and correction

The original 1/13 scores did not prove that the play cases were absent.
The run-bound `play.report.json` files contain all 13 results, including
12 failed device cases. The original host `play.log` contains only host
messages. The producer's `checks/gate/<run>/play.log` also contains the case
failure reasons. The saved captures and dumps confirm that the cases ran.

Two Verify defects hid that evidence in the merged result. Agent evaluation
did not request report accounting for a `verify` check unless the manifest
also declared report expectations. The gate also omitted a valid report when
the command exited with a failure. Verify now requests reports for every
`verify` check and retains valid case results after a failed command. A failed
command still fails. Individual failure reasons also reach `result.json`.

The fixes are on Verify main as `ec17948` and `32ecd1d`. Facet pins Verify
`f23ccea`. That commit also adds an audit change for styled UI and modal
occlusion. The audit counts in this report were recorded before that change.

The play host now records case starts and the complete formatted results in
`play.log`. It checks the exact selected case census before it writes scores.
An empty selection, a missing result, a repeated result or incomplete device
setup raises a harness error. The report also rejects universal scores that
have no matching case records or disagree with those records. Regression
tests cover a workspace-only report and numeric scores with no device cases.
Failed Studio probe calls also raise a harness error and prevent score output.
Their case report remains available for diagnosis. A failed UI assertion still
produces a recorded failed case and a valid score.

The universal geometry check used entire label rectangles as text bounds.
It now uses native `TextBounds`, `TextXAlignment`, `TextYAlignment` and padding,
and excludes text covered by opaque paint on a higher layer. Ancestor paint
does not hide its own child text. Tests cover separate text inside overlapping
label boxes, actual text overlap, and opaque and transparent modal paint.
After a failed universal case, the driver uses visible return controls to
close its route. It retains the original failure and logs recovery actions.
This prevents one failed geometry assertion from trapping later cases.

The strong reference also needed real UI corrections. Its Ready badge touched
the Rewards text. Its phone dock extended into native movement controls. The
badge now clears its text, the portrait phone dock scrolls above the movement
area, and Shop is the first dock action. Modal routes call the native PlayerModule controls'
`Disable` and `Enable` methods. These reference changes do not alter either
saved agent workspace. The native APIs above provide the engine observations
and controls; Compose does not own this plain-Roblox reference or test driver.
No Facet control or Compose source changed.
