## Missed targets and proposed Facet fixes

### Total tokens: 6.889x, including the 0.5x stretch miss

Each model request reads the retained history again, so total tokens grow
with the number of requests times the context size. Facet made 202 tool calls
against Plain's 94, at about 87,000 cached tokens per call against about
26,000. Plain's agent stopped after 853 seconds with 0/6 universal passes.
Facet's agent continued until every universal case passed. A longer run is
expected for a working result, but these Facet causes make it longer and
heavier than it needs to be:

| Cause | Evidence |
| --- | --- |
| Slow full verification | Four full `facet verify --tap` sweeps took 308 to 314 seconds each, 1,243 of 2,387 agent seconds. The agent ran about 16 progress polls during them. |
| Verbose verification output | Every full sweep prints 40 absolute screenshot paths, about 6,500 bytes. A summary line per device gives the same information. |
| Cascading static errors | One unsupported `width = "fill"` on `Text` and `Button` children produced about 60 error lines: each use repeats the same message, and each enclosing stack adds two overload lines. |
| Option lookup by source search | After those errors, the agent read 16,302 bytes of `layout_types.luau` matches, 10,365 bytes of type files and 22,131 bytes of Roblox definitions to find valid sizing options. |
| Front-loaded documentation | The agent opened about 50 documentation nodes, 68,852 bytes, before the first build. Seven requests named nodes that do not exist, such as `ProgressBar.card` and `Stack.layout`. |

Fix these in the Facet author kit and CLI, not in the eval:
- Make a full verification sweep faster, and print one capture summary line
  per device.
- Group identical static findings into one entry with a count and a bounded
  list of locations. Drop the overload lines that a nested option error
  already explains.
- When a leaf control receives a container sizing option, name the native
  way to size it in the hint.
- Resolve near-miss documentation names to the nearest node, and give the
  HUD recipe the dock, modal shop list and theme parts that this task opened
  separately.

The measured ledger does not isolate how much each fix saves. The transport
fallback and generic file-encoding retries are retained costs, not
attributed to Facet APIs.

### Phone mount: 1.258x, limit 1.10x, not established

Background load was unequal, so this ratio is not a target decision. Facet's
phone mount was slower although its checks ran on the quieter host, so the
candidate cause below still applies. The Facet-side cause to address is late responsive-layout convergence with
eagerly mounted alternatives. `src/ui/composition.luau` starts each Region at
form 1, creates every Form frame, observes each form's layout size, and then
selects a fitting form. The saved HUD supplies wide, medium and narrow forms.
The mount exclusions contain live wallet/progress updates from all three
forms, including hidden alternatives. Phone mount records 0.618 seconds
before the stable run, versus zero on desktop. The phone census is 563 UI
instances versus Plain's 62. The saved HUD also polls native touch-control
rectangles and applies a later reserve size. Facet's environment supplies
GuiService safe insets but no shared observed touch-control reservation.

Fix Facet's shared Composition initialization and HUD recipe so the initial
form and reserved geometry are ready before the first visible layout. Avoid
keeping complete live HUD alternatives mounted when native constraints can
describe the layout; use Compose ownership to mount only the selected form.
Where measured alternatives remain necessary, cache settled measurements
and avoid restarting unrelated layout work. The native APIs checked in the
source are UIListLayout, UIFlexItem, UISizeConstraint, ScreenInsets,
GuiService:GetGuiInset(), GuiObject.AbsolutePosition/AbsoluteSize and
ContextActionService:GetButton(). Compose already provides cells, watches,
conditional ownership and cleanup; no second scene graph is needed.

This is a source-backed diagnosis and proposed fix, not a causal timing
isolation. The sample cannot assign the entire 0.624-second arm difference
to one function. A follow-up should profile the Facet initialization and
then repeat the unchanged paired measurement. No timing token, check,
scenario, budget or reference should be changed to make this result pass.
