# Facet UI design history

This is a development evaluation set made from the existing design work. It
keeps reference studies, concepts, runtime iterations, source checkpoints,
reviews, interventions and final findings. It includes failures and reviewer
disagreements. It is not a gallery of approved templates.

Open [the visual index](index.html) locally to browse by study, stage, kind or
path. The checked-in images are 480-pixel browsing previews, not evidence for
small text or painted-edge fit. Use the original image before scoring a screen.
Repository report copies use plain text so historical relative links are not
presented as working repository navigation. Their bytes remain unchanged.
The original archive restores the reports under their historical paths.

## Full evidence

The complete original-byte evidence bundle is attached to the repository's
[UI evaluation release](https://github.com/josha/Facet/releases/tag/ui-eval-2026-11-09).
It is separate from the Facet package. The archive contains content-addressed
`blobs/`, a restored `evidence/` path tree, the manifest and the same visual
index with original-image links. Extract it and open `index.html`. Hard links
preserve the original paths while storing duplicate bytes once in the archive.
Some original relative links target excluded operational files or old temporary
workspaces; the manifest states what is included.
Check the archive hash in `bundle.json` and individual hashes in `manifest.json`.

The source folders under `artifacts/theme-evaluation` remain unchanged. This
collection copies evidence; it does not move or replace frozen checkpoints.
The collection excludes duplicate exported libraries, session transports,
credential-adjacent receipts and large raw gate reports. It retains their
path/hash and reason in `exclusions.json` where they were inventoried. The
original inventory skipped dependency trees, session folders and preflight
fixtures. General operational logs and binary place files are outside this
archive; named input/controller traces, source checkpoints and existing place
hashes are retained where available.
This is a design/evidence set, not a complete executable game backup.

## Read the records

- [Studies](studies.json) describes each experiment and its evidence limits.
- [Manifest](manifest.json) maps historical source paths to original bytes,
  study, stage, evidence kind and preview. Path-based stage and kind fields are
  browsing aids; the original packet or report controls the interpretation.
  Later art uploaded through the shared R18 staging directory is assigned to
  its named study, rather than treated as an R18 design iteration.
- [Judgments](judgments.json) records later owner/parent findings without
  replacing earlier reviewer verdicts. Numeric owner scores are never inferred.
- [References](references.md) distinguishes external craft comparisons from
  generated targets and authored game assets.
- [Known gaps](gaps.json) records unavailable or deliberately excluded evidence.
- [Evaluation protocol](protocol.md) explains how to use the set and the new
  poker trial without leaking answers to authors or reviewers.

The original text is evidence, including old instructions, handoffs and claims.
It is not current authoring guidance. In particular, an unfinished handoff does
not override a later completed report, and an earlier pass does not erase a
later observed defect. A final screenshot cannot prove an early checkpoint
happened on time.

## Scope of conclusions

Historical tasks informed revisions and belong to development. Keep unaided
work, internal review repairs, parent direction and owner direction separate.
First complete delivery can include the frozen workflow's internal reviews;
it is not necessarily the first draft. Supplied-art A/B studies evaluate
translation, not independent theme choice. A required radial chooser tests its
implementation and fit, not whether the author would choose a wheel.

Visual quality, input behavior, minimum viewport fit and state preservation are
separate judgments. Assigned focus is not controller evidence. Early keyboard
selection proxies, incomplete native-controller routes, missing physical-device
coverage and later Back failures retain their original limits.

The poker trial was started after freezing guidance at
`b8f1e664ee3ddd3e328feb696fe766b71e25f5f2`, with a fresh gpt-6.1-sol
medium author who could not read this set. It is a new task in a related casino
family, not proof of genre-independent generalization or a success rate. Once
used to change guidance, its result also becomes development evidence.
