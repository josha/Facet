# Game HUD additions

The Showcase exposes existing toasts in All controls → Indicators. Leaving
the example dismisses its notifications. The Screen-anchored HUD demonstrates
meters and reservations shared with transient surfaces. World marker placement
has its own nested Layout page.

## Decisions

- Extend ProgressView with segmented bars, a delayed damage trail, and explicitly
  sized circular readouts. Reuse its value model, theme slots, and motion clock.
- Publish presenter-owned HUD reservations as reactive window-space rectangles and
  edge insets. Toasts publish their measured occupied space; other independent
  surfaces can reserve and release space. Consumers opt in, avoiding feedback
  between the region that reserves space and the layout that yields to it.
- Add a pure world-marker placement function: priority ordering, edge clamping,
  bounded displacement, exclusions, and explicit hidden reasons. Extend the world
  anchor adapter to optionally retain offscreen directions and test occlusion.
- Keep game rules, target selection, and marker copy in the caller. Native
  ProximityPrompt.HoldDuration already supplies holding for proximity actions.
- Use the existing screen-anchored HUD to demonstrate coordination rather than
  add a second HUD demo or a second layout engine.

## Verification

Tests must first fail for the missing behavior, then cover geometry, reactive
changes, teardown, reduced motion, invalid specifications, and Showcase navigation.
Run full verification and rebuild the package after implementation.
Initial Studio discovery returned no connected instances; the live follow-up below
records the later connected session.

The fresh-context review found and prompted fixes for marker branch memo retention
and reservation recovery after an invalid toast. D-pad-only navigation tests cover
390px and ten-foot 1920px HUD layouts at +14 preferred text; four-input tests cover
HUD actions and marker controls across a resize.

## Live follow-up, 2026-09-16

The connected `Facet-Showcase.rbxl` was exercised with Studio MCP pointer and
keyboard input. The updated toast source and subsequent fixes were synchronized
into that session before testing; the built place remains the file deliverable.

- Show toast followed by Test input raised the visible button count to 1 while
  the notification remained visible. Enter raised it to 2.
- HUD Take damage changed health from 84 to 59. Keyboard Down/Enter selected
  Restore health and changed it to 100. Showing a notification shifted the
  timer from y=5 to y=132 and kept it below the toast.
- Live inspection caught the compact health form still using the fixed initial
  value. It now shares the reactive health text; the regression failed with
  `expected 84 to be 59` before the fix. The Pixel Quest phone preview displayed
  100, then 75 after Take damage, in the compact form.
- Pixel Quest phone preview rendered the world-marker page and accepted its
  controls: the objective clamped to the right edge, nearby markers separated,
  and simulated occlusion removed supplies. This tests the layout demo, not
  physical world raycasts.
- Live inspection caught left-aligned glyphs inside the centered gauge label.
  Both the central and below-ring readouts now declare centered text alignment.
  Their regression checks failed before the fix; the live circular readout then
  reported `TextXAlignment.Center` and appeared centered in the ring.
- Studio output contained the Showcase startup line and no runtime errors in
  the inspected session. Injected ButtonA did not activate the toast probe;
  native gamepad delivery and physical touch/console verification remain pending.
  Headless gamepad checks are not a substitute for that evidence.

The final full verification report is `artifacts/verify/latest-full.json`; runtime
source changes also require the offline package build and status check.
