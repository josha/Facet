# ADR-0004: Input verification scope — UI-INPUT-002 deferred to Phase 1; UI-INPUT-003 split harness

- **Status:** Accepted (2026-07-19)
- **Context:** The fresh-context Phase 0 gate verification raised two input findings.
  1. **UI-INPUT-002** ("PreferredInput changes hints/emphasis only; no remount") had `firstGate: phase-0-foundation`, but Phase 0 has no mounted renderer, so "no remount" is structurally unprovable now — the Studio spike could only confirm the API surface (`PreferredBinding` readable, nil in a keyboard-only session). Same shape as the WorldTarget situation (ADR-0003).
  2. **UI-INPUT-003** ("scriptable test input drives the same action pipeline as real input") is contradicted by the engine in its literal form: the Studio spike proved `InputBinding:Fire()` (Scriptable) drives its action directly and **bypasses cross-context priority/Sink arbitration**, while real key events do respect arbitration (artifacts/studio/ias-spike.json T1–T3).
- **Decision:**
  1. `UI-INPUT-002.firstGate` moves to `phase-1-minimal-screen`, where a mounted control's hint binding can be shown to update without remount. The Phase 0 `input-action-spike` gate check no longer cites UI-INPUT-002.
  2. UI-INPUT-003 is restated as the **split harness** (the design's documented recoverable fallback): scriptable bindings validate the binding→action pipeline (typed state, dedup, enable/disable, context disposal) headlessly and in Studio; **cross-context priority/sinking is validated with real or MCP-injected key events at engine gates** (`user_keyboard_input`). Controls never bypass the action layer. The Phase 0 gate records this as PASS **with the deviation named** (the spike artifact carries `PASS_WITH_DESIGN_IMPACT` + `designImpact`).
- **Consequences:** requirements.json restates UI-INPUT-002/003 accordingly. Phase 1's exit gate must include (a) a preferred-input hint change on a mounted control without factory rerun, and (b) at least one Studio arbitration trace via injected real input alongside the scriptable action traces. Engine arbitration checks remain Studio-session-bound (not headlessly rerunnable) — accepted as the §15.5 differential-check pattern. Conformance foils (fusion/imperative) are not determinism-guaranteed per-check; only the selected core's scorecard is byte-stable (phase-gate verifier finding 4, accepted).
