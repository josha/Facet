# Game UI design

Use the current use-facet skill. Start with the requested task and the product's
visual direction, then choose the controls and contracts that implement it.
For a new game direction, design one representative screen with deliberate
subject scale, typography, choice surfaces and action emphasis. A finished
native prototype can establish a graphic style; an illustrated direction can
start with an original concept and reusable art. Inspect the real Studio screen
and repair its visual defects before repeating the treatment. The skill owns
the review sequence; this reference does not add another required workflow.

Choose layout and visual treatment from the task, content, input and available
room. Give a game screen type, materials, shapes and feedback that express its
world and tone. A new accent on neutral panels alone rarely establishes that
identity. Use image-based surfaces when the direction benefits from them;
preserve standard controls and their behavior. A professional mail app, dense
text tool or Studio plugin can use quiet, familiar styling. The skill's
examples and example themes show working relationships. They are not required
features, skins or dimensions. Read patterns for another relationship and
compact compositions when room is constrained; do not load every reference
before building the first screen.

Use [Map](Map.md) for recipes and exact control contracts. Capture the changed
states in their real context at the supported sizes the host can show. Fix one
visible cause before you repeat the structure. Keep sequential steps inside a
stable navigation surface.
A passing typecheck or a control catalog is not a visual or behavioral review.
Compare the rendered task with the visual references before delivery; do not
wait for the user to request the first visual critique.
Plan readable text areas, selected and focused states, and stable action space
with the visual direction. Inspect those states and the accepted result in
the first build. Preserve the direction when repairing contrast or fit.

Older design chapters remain available for background reading. They are not a
second required reading path alongside the current skill.
