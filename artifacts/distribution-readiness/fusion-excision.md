## 6. `tools/check_no_fusion.py`

Scans `src/`, `examples/`, `skills/`, `tests/`, `bench/`, `package/`; every
script `Source` in a `.rbxmx` twin of the built model (through
`tools/build_model.sh`, reusing `check_library_purity.model_scripts`); and
`games/RascalRally/code/{src,tests}` when present. A missing root is a reported
SKIP, never a silent pass.

Four rules, most specific first so each can be the reported one:
`fusion_adapter|fusion_headless|fusion_lune_external`, `vendor/Fusion`, a require
string containing `fusion` in any case, and `\bFusion\b` **case-sensitive**
(`confusion` is ordinary English here). Any directory named `vendor` is a
violation on its own.

Structural exclusion: `examples/gallery/examples/words/*.luau` (SCOWL dictionary
data). Two named allowed mentions, each one path plus one rule, with a reason and
a removal condition:

- `tests/theme_docs.spec.luau` × `identifier` — the fixture for
  `docs/guide/14-choosing-a-ui-library.md`, the one public document the owner's
  rule 5 allows to compare Facet with other libraries.
- `package/README.md` × `removed-module` — the package verifier's own deny list,
  written out in prose. Naming a forbidden token is the opposite of depending on
  it. **This entry should be removed** once the package workstream drops the
  stale `fusion_adapter` token from that list.

`--selftest` proves each rule fires under its own name, proves `confusion` does
not fire, and proves each allowlist entry is scoped to its own path by planting
the same pattern in a file that is not the excused one.

Root-level files are deliberately out of scope: `README.md:194` names Fusion in
the row for the sanctioned comparison guide, which rule 5 permits.
