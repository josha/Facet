# theme-packages-and-skinning acceptance ledger

**Gate:** `theme-packages-and-skinning` (roadmap Step 3.5) · **Created:** 2026-07-24 ·
**Contract:** `docs/plans/agent-execution-contract.md` §2 · **Matrix:** `docs/plans/studio-device-verification.md`
**Governing doc:** `docs/plans/theme-packages-and-skinning.md`. Step 2 (`native-stylesheets`)
is complete and is not reopened by any row here; Step 3's control vocabulary is the
coverage target for every "all controls" row.

Status values are the contract's honest states: `PASS_AUTOMATED`, `PASS_PHYSICAL`, `PASS_HUMAN`,
`FAIL_PRODUCT`, `FAIL_ENVIRONMENT`, `PENDING` (automated work not yet performed),
`PENDING_PHYSICAL`, `PENDING_HUMAN`. A row cannot pass through a different, easier row; evidence
levels are the contract §3 ladder. Every `PASS_*` must cite an artifact produced by a tool run
in the session that set it. **All rows start PENDING; a status changes only when its artifact
exists.**

Stage-3.5 acceptance centerpiece (contract §9): *a clean consumer builds Fantasy Parchment
through public docs/APIs; its nine-slice panels/control chrome and every package install/swap
run in the mounted all-controls fixture; palette, effective font/metrics, solved/actual/hit
geometry, states, adaptive paradigms, fallbacks, focus/resource identity, Style Editor
synchronization, documentation drift, and flat-versus-ornate cost have paired evidence across
the device matrix.* A screenshot of a themed screen without its paired geometry/state trace is
insufficient for every row below.

## Notes

- Feasibility artifacts follow `luauui-studio-spike/1`; implementation artifacts follow the
  scenario export schema (`luauui-scenario/1`) written by the verification surface.
- Captures are real PNGs on disk under `artifacts/theme-packages-and-skinning/captures/`,
  taken with `tools/studio/capture_viewport.sh` (single-window capture only — never region or
  full-screen; see `artifacts/authoring-adaptive-ui/NEXT-SESSION.md` §6), named
  `TP-<row>_<fixture>_<profile>_<theme>_<state>.png`, and paired with a trace that records
  what state they show.
- Studio preflight (contract §4) is embedded in each Studio session artifact under `preflight`.
- TP-A9's automated proof edits/installs through the public surface a real consumer would use.
  What it cannot prove is a human finding the workflow pleasant or the result beautiful — that
  judgment is TP-P1/TP-P3 and is never closed by automation.
