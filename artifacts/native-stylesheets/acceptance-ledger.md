# native-stylesheets acceptance ledger

**Gate:** `native-stylesheets` (roadmap Step 2) · **Created:** 2026-07-24 · **Contract:** `docs/plans/fable-execution-contract.md` §2
**Governing docs:** `docs/plans/roblox-native-audit-corrections.md` (wins on conflict) → `docs/plans/roblox-native-stylesheets.md` (Rev 2).

Status values are the contract's honest states: `PASS_AUTOMATED`, `PASS_PHYSICAL`, `PASS_HUMAN`,
`FAIL_PRODUCT`, `FAIL_ENVIRONMENT`, `PENDING` (automated work not yet performed),
`PENDING_PHYSICAL`, `PENDING_HUMAN`. A row cannot pass through a different, easier row;
evidence levels (E0–E5) are the contract §3 ladder. Every `PASS_*` must cite an artifact
produced by a tool run in the session that set it. **All rows start PENDING; a status changes
only when its artifact exists.**

Stage-2 acceptance centerpiece (contract §9): *a running screen changes through a native
style-rule/token change without a Luau source edit; native and app states change the intended
rules; explicit writes no longer defeat stylesheet-owned properties; focus and mount identity
survive.* A generated stylesheet, unit test, or screenshot without runtime state evidence is
insufficient for any row below.

## Notes

- Feasibility artifacts follow `luauui-studio-spike/1`; adoption artifacts follow the scenario
  export schema (`luauui-scenario/1`) written by the verification surface (`examples/gallery/scenarios/`).
- Captures are named `NSS-<row>_<scenario>_<profile>_<state>` and recorded as capture ids in the
  paired JSON (Studio `screen_capture` has no disk sink — recorded id + paired trace is the capture evidence).
- Studio preflight (contract §4) result is embedded in each Studio session artifact under `preflight`,
  produced by the shared `probe` scenario + the preflight steps in the session driver.
- NSS-A3's automated proof edits the SAME DataModel instances the Style Editor edits (rule
  `SetProperties` / token attributes). What it cannot prove is a human finding those controls in
  the editor UI — that judgment is NSS-P1 and is never closed by automation (contract §3, E5 row).
