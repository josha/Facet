# authoring-adaptive-ui acceptance ledger

**Gate:** `authoring-adaptive-ui` (roadmap Step 3) · **Created:** 2026-07-24 · **Contract:** `docs/plans/agent-execution-contract.md` §2
**Governing docs:** `docs/plans/roblox-native-audit-corrections.md` (wins on conflict) → `docs/plans/swiftui-parity-next.md`
(Milestones 0, A, B) → `docs/plans/studio-device-verification.md` (the five-view matrix) → `docs/reference/swiftui-parity.md`.

Status values are the contract §2 honest states: `PASS_AUTOMATED`, `PASS_PHYSICAL`, `PASS_HUMAN`,
`FAIL_PRODUCT`, `FAIL_ENVIRONMENT`, `PENDING` (automated work not yet performed), `PENDING_PHYSICAL`,
`PENDING_HUMAN`. A row cannot pass through a different, easier row; evidence levels are the contract §3
ladder (E0–E5). Every `PASS_*` must cite an artifact produced by a tool run in the session that set it.
**All rows start PENDING; a status changes only when its artifact exists.**

Stage-3 acceptance centerpiece (contract §9): *invalid public authoring fails at the boundary; the actual
gallery drives each control through available real Studio input; portrait, landscape, desktop, and
console-emulated layouts have geometry and captures; layout/input hot changes retain valid state.*
